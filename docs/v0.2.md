# V0.2 域名网关候选版

## 已通过 CI #17 的基础网关
- 1–64 个显式域名到本机 relay 端口的静态映射；拒绝重复域名、通配符、无效端口、配置注入。
- Rust CLI 生成独立 Nginx HTTP/HTTPS 网关配置；不会修改现有 Nginx 站点或自动重载生产服务。
- TLS 1.2/1.3，使用管理员提供的 SAN 证书及私钥；拒绝未知 SNI、未知 Host 和 SNI/Host 不一致。
- HTTP/1.1、WebSocket upgrade、固定上游、代理转发头重写、基本请求体和超时限制。
- Linux 真实 Nginx + Rathole E2E，Windows Rust 单测及原有隧道回归；本地临时域名和独立信任测试证书，不使用生产 DNS。

## 使用示例（Linux 测试环境）
    localtunnel gateway-http /tmp/lt-http.conf 127.0.0.1:18080 web.example.test 20800 api.example.test 20801
    localtunnel gateway-https /tmp/lt-https.conf 127.0.0.1:18443 /tmp/cert.pem /tmp/cert.key web.example.test 20800 api.example.test 20801

先确保前置 relay 已启动且映射端口匹配；使用空的专用 Nginx prefix、绝对配置文件路径，执行 nginx -p <prefix>/ -c <config> -t 后才启动。测试时可使用 curl --resolve 指定回环地址；HTTPS 使用受信任测试证书，不关闭证书校验。证书文件不得提交 Git。当前采用同一 SAN 证书覆盖本次配置所有域名。

## 动态路由与证书预检增量（待新 CI）

Linux 专用的预览网关仅允许 127.0.0.1 高位端口及权限受限的独立目录，禁止重载系统 Nginx。可信操作员负责目录及映射端口授权，不能将这些命令直接开放给非可信用户。启动示例：

    mkdir -m 700 /tmp/lt-managed
    localtunnel gateway-init /tmp/lt-managed 127.0.0.1:18080 web.example.test 20800
    nginx -p /tmp/lt-managed/ -c /tmp/lt-managed/nginx.conf -g 'daemon off;'

在另一终端执行：

    localtunnel gateway-apply /tmp/lt-managed 127.0.0.1:18080 web.example.test 20800 api.example.test 20801
    localtunnel gateway-apply /tmp/lt-managed 127.0.0.1:18080 api.example.test 20801
    localtunnel gateway-apply /tmp/lt-managed 127.0.0.1:18080

最后一条禁用所有域名。更新使用独占锁、候选配置 nginx -t、原子替换、reload、回环 revision 探测；探测失败尝试恢复旧配置及运行版本。异常中断后须检查 localtunnel.lock / nginx.previous.conf，不自动删除恢复证据。探测只确认配置已激活，不等于每条业务映射健康，也不保证已建立的旧 WebSocket 立即中断。当前动态功能仅 HTTP 且只针对已经存在的 relay 端口；不涉及隧道热更新。失败回滚路径仍需专项故障注入测试。

证书预检示例（OpenSSL 3，指定明确可信 CA bundle）：

    localtunnel cert-check /tmp/fullchain.pem /tmp/privkey.pem /tmp/ca.pem 14 web.example.test api.example.test

验证剩余有效期、私钥匹配、可信链、服务端用途、域名。支持无需交互密码的私钥。CI 用自签临时信任证书覆盖有效、临期、错误域名、错误私钥情形，不代表公共 CA 签发测试。

ACME 后续：域名控制权验证通过后，在专用授权测试环境使用 ACME staging 与 DNS-01 或 HTTP-01；验证证书预检和 HTTPS 重载后，才启用正式签发/续期。当前没有自动申请、续期或生产 HTTPS 动态重载代码；以下独立预览网关增量实现 HTTPS 动态重载候选功能。不要在免费 Runner 中长期托管生产服务。

## HTTPS 动态路由和证书轮换增量（待 CI）

独立 Linux 预览网关支持新的 TLS 管理命令，仍限定 IPv4 回环高位端口，并使用另一回环高位端口作为只返回 421 和 revision 的探测入口。证书、私钥及 CA 路径必须由可信操作员提供，至少保留一个有效域名。初始配置与更新均执行证书预检；更新完成后要求 revision 生效及每个域名通过 curl 的真实 TLS 证书/主机名验证。保留 /.localtunnel-revision 为网关自身探测路径，不转发至本地应用。更新失败尝试恢复旧配置；故障注入专项验收尚未完成。

    mkdir -m 700 /tmp/lt-tls
    localtunnel gateway-tls-init /tmp/lt-tls 127.0.0.1:18443 127.0.0.1:18444 /tmp/cert-v1.pem /tmp/key-v1.pem /tmp/ca.pem 14 web.example.test 20800
    nginx -p /tmp/lt-tls/ -c /tmp/lt-tls/nginx.conf -g 'daemon off;'

在另一终端更新：

    localtunnel gateway-tls-apply /tmp/lt-tls 127.0.0.1:18443 127.0.0.1:18444 /tmp/cert-v2.pem /tmp/key-v2.pem /tmp/ca.pem 14 web.example.test 20800 api.example.test 20801

使用不可变、版本化的证书文件路径，保留旧证书和私钥供回滚；不要原地覆盖或提前删除旧文件。Linux CI 使用两个独立测试证书验证新证书信任、旧信任拒绝、域名增删、错误私钥拒绝及主进程 PID 不变。探测成功仅表示网关加载新配置并可验证 TLS，不保证每个业务上游健康或存量长连接立即中断。运行依赖 Nginx、OpenSSL 3、curl。自动 ACME、真实 DNS 所有权和生产公网验收仍待完成。
