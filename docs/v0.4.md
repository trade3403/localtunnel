# V0.4 管理服务（首个开发增量）

沿用架构文档的 Axum + SQLx/SQLite 方案，新建独立 crate `crates/server`，不改变现有核心和桌面锁文件。首个增量只提供 Linux 回环管理服务骨架、真实数据库迁移、健康和就绪接口，不启用匿名用户/设备/映射接口、不应用实际隧道或网关配置。

本地开发（Linux，非生产）：

    mkdir -m 700 local-data
    cargo run --manifest-path crates/server/Cargo.toml -- local-data 9000
    curl http://127.0.0.1:9000/healthz
    curl http://127.0.0.1:9000/readyz

数据目录应由可信运行账户独占并保护其父目录；不接受组或其他用户可访问的目录及数据库符号链接。当前不是完整文件系统安全审计。初始迁移包含 users、devices、nodes、domains、mappings；独立凭据摘要、密码哈希字段、归属复合外键、域名和节点端口唯一约束、映射默认禁用。没有初始管理员或默认密码；没有登录、设备注册、域名验证、状态上报及配置应用，不能用于正式管理。

首轮 CI #1/#2 已通过，锁文件从两份独立 CI 日志逐字比较一致后提交。后续 CI 使用 cargo test/build --locked 并检查锁文件无变化；基础工程严格锁定 CI #3/#4 已通过，随后进入管理员认证。测试覆盖实际 Axum 监听、数据库迁移/重启、约束拒绝、就绪失败与不安全目录；无公网、无生产数据。

## 设备注册与认证（CI #9/#10 已通过）
- 管理员 POST /api/v1/devices/pairing-code 签发 10 分钟一次性 256 位随机配对码，重新签发轮换旧码；管理员密码/角色/启用状态变更撤销未使用码。配对码在有效期内独立于登录会话，避免登录注销影响配对操作。
- POST /api/v1/devices/enroll 接收 pairing_code/name；原子消费并创建归属设备，返回 id/device_token，仅保存类型区分的 SHA256 摘要。设备凭据长效，须由客户端保护；设备 GET /api/v1/devices/{id}/identity 只能认证自身，实时检查所有者和设备启用状态。
- 管理员 GET /api/v1/devices?after=<id> 每页最多100条，仅自己的设备；POST /api/v1/devices/{id}/revoke 仅本管理员的启用设备可操作，禁用、轮换凭据摘要、递增 revision。吊销仅阻断管理 API，不代表正在运行的 Rathole 数据隧道已停止。所有者重新启用后未被显式吊销的设备可继续认证。
- 4KiB请求体，注册全局每进程60次/分钟预算，重启重置；不作公网限流保证。仍仅回环预览，无客户端 DPAPI 配对集成、配置同步、心跳或真实公网验证。新增真实并发兑换、权限隔离、重启、过期、吊销测试。无新增依赖。

## 设备配置与心跳（CI #11/#12 已通过）
- GET /api/v1/devices/{id}/config：设备自身 Bearer 认证，读取同一 SQLite 快照的 revision 和所属映射期望元数据，最多64条（超限拒绝而不截断）。包括停用映射；不下发隧道 Token、服务端公钥或可执行配置。映射增删改触发设备 revision 变化，节点与域名详情尚未加入快照。
- POST /api/v1/devices/{id}/status：设备上报 reported_revision（0允许未应用）和 reported_state（idle/starting/running/error），未来版本拒绝，落库采用服务器时间及同一写操作检查授权。建议30秒心跳。客户端状态为自报，非真实转发探测；按最后接收顺序记录，不保证消息排序。
- GET /api/v1/devices/{id}/status：仅设备所属管理员可查询。90秒内心跳且设备启用才判 management_online；configuration_current 仅代表在线且自报版本等于期望版本，不保证配置实际应用或隧道连通。离线时保留最后自报状态；账号禁用/角色变更及设备凭据/启用变化清除旧心跳。
- 新增真实 HTTP/SQLite 测试，覆盖空快照、版本变化、跨设备/账号隔离、未来版本拒绝、心跳过期（测试数据库时间注入）、重启和吊销。当前仍为回环控制面预览，映射写 API、节点与域名验证、实际配置应用和客户端集成待开发。

## 管理员映射 CRUD（CI #13/#14 已通过）
- GET/POST /api/v1/mappings，GET/PATCH/DELETE /api/v1/mappings/{id}。管理员仅查看/操作自己所属设备映射，列表按 id 游标每页最多100条。创建需要既有启用设备/节点；HTTP/HTTPS 需要自己所属域名记录，TCP 不允许域名。未验证域名仅能创建禁用草稿。节点和域名记录的管理接口尚未实现。

- PATCH 支持 local_port、bind_port、enabled=false；expected_revision 必填，过期版本409。设备/节点/协议/域名不可通过此增量修改，需要新建草稿。已启用记录只允许单独停用，禁止直接改端口或删除。DELETE 使用 expected_revision 查询参数，仅禁用记录可删。所有写操作检查当前会话及归属；设备配置版本沿用已有触发器变化。
- 新增真实HTTP集成测试：创建/查询/修改/删除、跨账号与设备令牌拒绝、端口/域名冲突、版本冲突、激活门禁、重启及64条上限。节点/域名和遗留启用状态使用数据库测试夹具，不代表生产激活或DNS验证。无新增依赖。

## 节点与域名所有权（CI #15/#16 已通过）
- 共享节点由可信本地操作员执行 `localtunnel-server --add-node <data-dir> <name>`（输出节点id），`--set-node-enabled <data-dir> <id> <true|false>`；已有启用映射时拒绝停用。管理员 GET /api/v1/nodes 只读共享目录（每页100条），没有跨账号节点写权限。节点只是元数据，不代表真实中转服务器已部署。
- GET/POST /api/v1/domains、GET/DELETE /api/v1/domains/{id}、POST /api/v1/domains/{id}/challenge、POST /api/v1/domains/verify（domain_id）。小写规范化、严格 hostname 校验、全局唯一、所属隔离，每管理员最多100个。创建生成256位随机公开TXT证明，记录名 _localtunnel.<hostname>，值 localtunnel-verification=<token>。轮换挑战清除验证时间；有启用映射禁止轮换。有映射引用拒绝删除。
- 验证调用固定 /usr/bin/dig（Linux dnsutils），系统递归 DNS，TCP、2秒查询超时、一次尝试，最多两个并发工作者。只接受 NOERROR、精确 owner 的完整单段 TXT 值，拒绝 CNAME 替代/子串。操作员可用 LOCALTUNNEL_DNS_RESOLVER 指定 IPv4 回环 DNS 地址:端口，HTTP 无法设置。DNS 信任系统解析器，不声称 DNSSEC 验证。确认后原子复查挑战及管理员授权写入 verified_at；失败不更新历史成功时间。验证新鲜度、域名转移/未验证抢占策略、周期复验、生产TLS/实际启用门禁仍待后续实施。
- CI 使用实际本地 TCP DNS 测试服务及真实 dig 查询，不需要公网域名、不注入验证成功。旧映射草稿门禁保持；无新增 Rust 依赖。

## 管理配置到实际 HTTP 隧道的操作员预览（CI #17/#18 已通过）
仅 Linux 同机回环、单个 HTTP 禁用草稿；不开放生产 API 激活，不支持 HTTPS/TCP 公网入口。可信本地操作员应先停止管理 API，避免并发修改；所有文件及进程由该操作员独占，不能将下列命令暴露给远程用户。设置 LOCALTUNNEL_CORE_CLI 为可信绝对路径、LOCALTUNNEL_SERVER_PRIVATE_KEY/PUBLIC_KEY 为本次 Rathole 密钥，使用：
- `localtunnel-server --export-preview <data-dir> <mapping-id> <revision> <relay-port> <bundle-name>`：检查当前版本、启用设备/节点/管理员及5分钟内TXT验证时间；使用现有核心 CLI 生成独立随机隧道 token 的 server.toml/client.toml 和非秘密 manifest.json，目录0700，配置0600，不覆盖已有目录。密钥仅传给相关生成子进程，不输出；客户端和服务端配置均为敏感材料，勿上传。验证时间不代表连续DNS所有权。
- 使用可信固定 Rathole 分别运行两份配置，操作员负责进程生命周期。创建 data-dir 内独立0700空目录 gateway；`--preview-gateway <data-dir> clear 0 gateway <listen-port> init` 初始化空独立 Nginx；由操作员启动专用 nginx -p ... -c ... -g 'daemon off;'。再以 mapping-id/revision 代替 clear/0、mode=apply 通过现有核心应用 HTTP 路由；clear 0 apply 清空路由，即使后续凭据撤销也可清空。复用现有 Nginx 检查、revision 探活、失败恢复机制，不动系统 Nginx。
- CI 实际由 API 创建设备/域名/映射、真实本地DNS验证、生成配置、启动实际 Noise Rathole 与 Nginx、核对随机正文、错误Host拒绝、真实清空路由，另通过已有备份阻断新 apply 验证旧文件和真实旧流量保持。此失败属于应用前保护，不是新配置reload后失败的回滚注入。数据库仍为禁用草稿，未标记运行成功。尚未实现后台一键应用、自动进程监督、跨进程一致性、自动吊销停止隧道、HTTPS证书应用及新配置加载后故障专项验收。无需新 Rust 依赖。

## 实际业务探测与应用历史（CI #19/#20 已通过）
- 新增 core gateway-apply-checked，单个 HTTP 路由先经过 nginx -t、reload、候选 revision 实际生效探测，再用固定回环地址及目标 Host 发送真实 GET /，仅接受 HTTP 200 和完全相同的 1–65536 字节预期正文。curl 禁用用户配置/代理、不跟随重定向、限制时间和响应大小；失败走既有真实文件恢复/reload/旧 revision 探测。预期正文由可信本地操作员提供，不接受网络调用方提供 URL 或命令。
- 管理 CLI：--preview-gateway <data-dir> <mapping-id> <revision> <prefix-name> <listen-port> apply-checked <private-expected-body-filename>。文件位于私有 data-dir，名称受限、普通文件、0600 或更严格；不要包含敏感数据。保持停 API 后操作的预览限制。
- 第六迁移 preview_attempts 保存每次经过前置校验并准备调用 core 的网关操作，执行前持久化 pending，执行后 succeeded 或 failed_or_unknown；若进程异常中断可能留下 pending，需要操作员核对真实运行状态。无密码、Token、正文或私钥记录。仅本地数据库历史，不代表持续在线，失败状态不自动断言回滚成功；未实现历史 API、进程监督、自动撤销或跨进程一致性。
- CI 通过错误预期正文真实触发候选 reload 后业务探测失败，验证实际请求到达经 Noise 隧道的本地服务、旧文件逐字恢复、旧空网关返回421；再用正确正文应用并验证真实流量。另测试撤销后新 apply 被拒绝、操作员显式 clear 仍可执行，以及应用历史持久化。并未自动停止既有隧道。

## 本地前台隧道监督及撤销清理（CI #21/#22 已通过）
- Linux 可信操作员显式运行 `--supervise-preview <data-dir> <mapping-id> <revision> <relay-port> <bundle-name> <prefix-name> <listen-port> <expected-body-filename>`；设置可信绝对 LOCALTUNNEL_ENGINE、CORE_CLI 及预览所需密钥。必须使用已运行且完全专用的独立 HTTP 网关；监督器先清空它，再生成新私有 bundle，启动自己拥有的 Rathole 两个子进程，真实 relay 正文探测后调用受检 gateway apply。不会执行 HTTP 提供的命令或管理任意PID。
- 管理 API 可以运行以提交撤销操作；监督器每500ms检查版本、设备/账号/节点授权和5分钟TXT验证新鲜度，数据库错误也停止；子进程意外退出同样清理。停止时先终止并等待自己创建的 relay/client，再清空独立网关，即使清空失败也尝试停止两子进程。成功只代表该次清理完成，不代表公共端口/旧连接/其他进程均被停止。监督器锁防止同前缀的两个监督器并发；其他本地CLI仍需操作员协调。
- CI 在前一手工回归后通过实际API新建设备、开启监督器、真实HTTP正文、竞争锁拒绝、实际API吊销、监督器退出、网关421和relay端口不再返回内容进行验证。旧预览记录继续保留。
- 仍是单机单HTTP映射的自愿前台预览；未实现管理后台远程启用、HTTPS、跨主机、进程异常强杀后的孤儿自动收割/系统服务、连续DNS查询、生产密钥管理或跨进程原子一致性。操作员负责保护配置并确保同一前缀无其他业务；不要强杀监督器，若异常中断应核对锁及实际进程。无新增 Rust 依赖。

## HTTPS 管理配置与证书联动（CI #23/#24 已通过）
- `--export-preview` 扩展支持 HTTPS 草稿，保留版本、所属授权及近5分钟TXT校验，manifest 增加 protocol；原HTTP gateway和监督器仍只接受HTTP草稿，避免降级发布HTTPS。
- Linux 本地可信操作员：在 data-dir 内建独立0700证书版本目录（chain.pem、key.pem、ca.pem，均普通文件且0600或更严格，禁止符号链接、每文件最多1MiB）。证书路径由操作员控制，禁止远程设置；保留旧版不可变文件供回滚。独立网关目录0700，使用 `--preview-tls-gateway <data-dir> clear 0 <prefix> <listen-port> <probe-port> <cert-dir> init`，启动专用 Nginx 后，以 mapping-id/revision 代替 clear/0、mode=apply-checked 并追加私有预期正文文件名。两个监听端口均回环高位且不能与内部转发冲突。
- 空TLS配置拒绝所有握手，允许 init/clear 即使证书已过期（仍须提供存在、可由 Nginx 加载的证书/私钥）。非空只允许受检应用：证书至少剩余一天、链/密钥/域名检查、实际可信TLS revision验证、真实HTTPS GET / 的200及完全一致正文。失败沿用旧配置恢复、reload、旧revision探测；记录结果仍为失败或未知，不宣称持续可用。用 clear 0 apply 明确清除路由。第七迁移为应用历史加入 transport，原记录默认为http。
- CI 使用真实本地DNS、API HTTPS草稿、Noise Rathole、专用Nginx、两个版本的临时受信自签证书，检查错误证书、未知SNI、Host错配、证书轮换、候选业务失败后旧证书与流量恢复、撤销后拒绝新应用和显式拒绝握手。无真实公网、公共CA或自动ACME验收；HTTPS监督器、自动撤销已有HTTPS路由、后台启停、进程异常收割仍待开发。无新Rust依赖。

## HTTPS 前台监督与自动撤销（CI #25/#26 已通过）
- Linux 可信操作员可使用 `--supervise-tls-preview <data-dir> <mapping-id> <revision> <relay-port> <bundle-name> <prefix-name> <listen-port> <expected-body-filename> <probe-port> <cert-dir>`。仍须先初始化、启动独占专用 TLS 网关，并提供不可变私有证书目录、可信 core/engine 及 Rathole 密钥。HTTP/HTTPS 监督路径严格校验对应协议，共用进程生命周期、竞争锁、授权检查、真实 relay 正文检查；HTTPS 发布必须实际可信 TLS 握手、revision 与业务正文校验成功。
- 启动前拒绝探测端口与 relay/listener/upstream 冲突及证书目录与 bundle/prefix 冲突。运行中复查映射版本、账号/设备/节点授权及 TXT 验证新鲜度；撤销或失效后先终止自身拥有的 Rathole 两子进程，再尝试将 TLS 网关清空为拒绝所有握手。证书文件丢失等导致清空失败时仍停止子进程、返回失败，不保证网关已清空。不会管理任意 PID。
- 真实 CI 追加 HTTPS 草稿、监督器启动、可信证书正文、错误信任、协议/端口错误、竞争锁、实际 API 撤销、relay 不可达、网关仍运行但拒绝握手、历史核对。仍是单机前台预览，不表示已部署公网、持续DNS复验、证书自动续期、自动重启/孤儿回收或后台一键启停。无新增依赖。

## 管理启停请求与本地受控 worker（CI #27/#28 已通过）
