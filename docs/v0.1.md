# V0.1 开发说明（候选版，未验收）

先实现无需域名的 Rust 隧道配置工具和真实同机转发测试。复用 Rathole v0.5.0 独立进程，而非重写协议。V0.1 采用 Noise NK（固定服务端 X25519 公钥 + 每映射随机 token），不依赖证书；公网 HTTP/HTTPS 网关和 TLS 证书待 V0.2。上游老版本仅用于隔离 CI 验证，生产前必须审计、锁定校验和及升级策略。

构建：cargo build --release --locked。使用 rathole --genkey 在受控环境生成独立密钥。通过环境变量 LOCALTUNNEL_TOKEN（随机 32 字节 hex）、LOCALTUNNEL_SERVER_PRIVATE_KEY 或 LOCALTUNNEL_SERVER_PUBLIC_KEY 传入秘密/公钥。不要把私钥传给客户端。配置写入新文件，Unix 权限 0600；Windows 使用仅当前账户可读的目录。示例：

    localtunnel server-config server.toml 127.0.0.1:2333 web 20800
    localtunnel client-config client.toml 127.0.0.1:2333 web 127.0.0.1:8080

分别使用官方 Rathole 可执行文件运行两个配置，或者将 LOCALTUNNEL_ENGINE 设置为已验证可执行文件的绝对路径后执行 localtunnel run server.toml / client.toml。V0.1 不包含后台进程监督；优先由系统服务或测试脚本管理 Rathole 进程生命周期。

测试：cargo test --locked；cargo build --release --locked；python tests/e2e.py。Python 脚本在同一 runner 内创建真正的 HTTP fixture、临时密钥、relay 和 agent，验证错误 token、数据转发及 relay 重启重连。生成 report.json 和脱敏日志。Linux/Windows 免费云端 runner 自动执行。Windows 上游归档校验和参考 Scoop 清单；Linux 目前记录归档 SHA-256，未独立锁定，不用于生产发布。

限制：TCP、静态配置（最多 64 个映射）、回环目标和回环映射端口；无 GUI、动态域名、HTTP 网关、安装包、跨机器 NAT、公网 HTTPS 或生产部署。域名及公网服务器暂不需要，后续提供后单独完成真实公网验收。CI 结果未通过前不标记 V0.1 完成。

## 多映射增量

同一个 relay/agent 允许 1–64 个静态映射，每个映射使用独立随机 token。拒绝重复名称、服务端端口冲突、重复 token 与非回环目标。按映射顺序设置 LOCALTUNNEL_TOKEN_1、LOCALTUNNEL_TOKEN_2 等；两个配置中同名映射使用相同 token。示例：

    localtunnel server-multi server.toml 127.0.0.1:2333 web 20800 api 20801
    localtunnel client-multi client.toml 127.0.0.1:2333 web 127.0.0.1:5173 api 127.0.0.1:8080

新增 E2E 验证两个独立本地 HTTP 服务、32 次交错并发请求；CI 成功后发布 native CLI 及 SHA256SUMS（不含 Rathole/GUI，不是安装包）。尚未实现动态配置重载或域名网关。
