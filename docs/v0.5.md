## 管理 API 应用层资源保护

- 所有进入 Axum 的请求使用同一固定内存 token bucket，每秒补充120个、最多240个突发请求，超限429 + Retry-After: 1。基于单调时间，不读取代理头/用户自报IP，不保存无限客户端键；每个进程独立，重启重置。共享预算可能使本机合法请求也被限流。原登录/配对及DNS工作者门禁仍保留。
- 同时最多32个进入处理链的请求，不排队等待，超限503；12秒处理期限（含JSON body读取、SQL及handler），超时503并释放处理许可。已提交写入可能已生效，超时不保证事务撤销，客户端应查询状态而非盲目重试。独立 blocking 工作仍须各自保护，不能宣称全部取消。
- 请求目标 path/query 2048字节、解析后的header名称/值及分隔符合计16KiB、声明Content-Length 4096字节；已存在的JSON extractor 4KiB限制继续约束流式JSON。未读请求体的端点不宣称检查完整body。返回统一 no-store、nosniff、DENY、no-referrer，包括应用层拒绝和错误。
- 实际回环 E2E 检查大小上限和响应头，32个未完整发送的JSON请求占满并发，实际503、处理期限与容量恢复，真实突发429及补充后就绪恢复。新增令牌桶确定性单测，不使用假时钟代替真实回环测试。
- Tokio time feature 显式启用，依赖版本不变；现有 Rust/npm lock 门禁保留。
