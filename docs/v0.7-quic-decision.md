## 决策及约束

- 当前 QUIC Python 实验在有损尾延迟上显示潜力，但无损吞吐约为现有 Rust Noise/TCP 的1/14.4；1%损伤下仍只有约1/4.5。两种路径不同（Noise经真实外部TCP映射入口，QUIC relay内部直接开流），内核损伤覆盖本地fixture等全部腿，语言、缓冲、并发实现不同；不能把差值归因于协议自身，不能推论Rust QUIC性能。
- 保留现有TCP及UDP-over-Noise/TCP产品实现、配置兼容性和原有平台回归，不引入Python或Quinn运行时依赖、不增加产品QUIC监听器、不公开QUIC配置或传输能力、不发生产版本。保留现有全部QUIC实验及哈希锁 CI门禁，不按胜负改变断言。UDP支持与QUIC不绑定。
- 目前应用接纳限制不覆盖aioquic全部握手、内部stream缓存、连接及内核资源；显式重认证不等于自动重连或迁移。无跨机公网、长稳、安全审计和生产SLA证据。

## 重新评估门槛（未来，不阻塞本次UDP预览）

先设计同一语言/同等入口及fixture的Rust候选（例如Quinn），审计固定版本及完整依赖许可、供应链与安全边界；在独立主机或隔离veth两端仅对隧道链路施加可复现损伤，匹配payload、并发、连接生命周期、认证及资源预算。记录吞吐、p50/p95/p99、CPU、内存、重连成功率及长期稳定性，验证拒绝未授权流、过载隔离、故障恢复和回退。只有在可重复、目标真实负载下具备明确收益且无不可接受退化时再决定正式引入，保留Noise回退，不自动承诺QUIC上线。
