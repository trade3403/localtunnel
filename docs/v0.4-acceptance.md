## 本地使用入口（仅隔离开发环境）

Linux 需 Rust/Cargo、Node/npm、dnsutils、Nginx、curl >=7.84、OpenSSL；浏览器测试使用现有锁定 Playwright/Chromium。按 `.github/workflows/v04-management.yml` 使用 Ubuntu 24.04 免费 Runner，Windows 工作流见 `.github/workflows/v03-desktop.yml`。不需要付费 Runner 或生产凭据。

1. 在仓库根执行 `cargo build --release --locked` 与 `cargo build --release --locked --manifest-path crates/server/Cargo.toml`。由可信账户创建新的 0700 数据目录。
2. 使用 `crates/server/target/release/localtunnel-server --init-admin <private-data-dir>`，从受保护 stdin 输入 username/password JSON；不要将真实密码放在命令行、日志或提交中。再运行 `localtunnel-server --add-node <private-data-dir> <name>`（以上简写指同一个已构建二进制）。运行 `localtunnel-server <private-data-dir> 1431`，用本机 /healthz、/readyz 检查。
3. 进入 `apps/admin`，执行 `npm ci`、`npm run dev`，浏览器打开 http://127.0.0.1:1430。默认同源代理到本机管理端口1431。后台登录、设备配对、域名 TXT 验证、创建禁用映射草稿；启动只提交请求。
4. 真正预览运行须由可信 Linux 操作员预先配置专用本机网关、可信绝对 core/engine 路径及测试密钥、私有预期正文文件、HTTPS 私有证书目录，再按 [V0.4 详细文档](v0.4.md) 的 worker/resident 命令固定映射、版本、端口和协议。不可让 HTTP 请求指定命令或路径，不操作系统 Nginx；DNS 证明新鲜度5分钟，超过即停止受控预览，非长期生产机制。
5. Windows 安装包的管理配对只连接同一 Windows 主机的回环管理 API；CI 用 Windows 构建的真实 API 作为测试夹具，不宣称 Windows 服务端生产支持。与 Linux 同机预览是不同验收场景，不能把 Windows 回环地址指向远程 Linux。现有独立手动/SCM 隧道不由管理元数据驱动。
6. 故障后由可信操作员在专用端口关闭且网关仍运行时使用 `--recover-runtime <private-data-dir> <prefix> <request-id>`；不删除 guard、不任意杀进程、不自动复用失败配置。无记录、证书丢失或中断网关等情况需人工处理。

## 复现验收

以同一个提交执行完整四类工作流，核对 push/PR 所有运行结果；不只看某个绿灯或旧安装包。管理工作流逐一生成9个真实 JSON 证据，桌面工作流生成4个关键 JSON 证据，随后运行 `python3 tests/verify_v04_evidence.py management management-evidence` / `python tests/verify_v04_evidence.py desktop desktop-evidence`。缺任一要求字段、测试失败、依赖锁变更均不得通过。通过后保留 CI 链接、工件与对应 SHA；未签名包不是发布版。
