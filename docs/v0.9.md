# V0.9 多节点管理开发预览

## 已验收基线
从 V0.8 精确提交 3ef36b61459df7fb4a4470a2be3b1d2a23c53382 开始独立分支，V0.8 同 SHA 五项 PR CI 成功：[Hosted](https://github.com/trade3403/localtunnel/actions/runs/46000842684)、[Gateway](https://github.com/trade3403/localtunnel/actions/runs/46000842744)、[Native](https://github.com/trade3403/localtunnel/actions/runs/46000842781)、[Management](https://github.com/trade3403/localtunnel/actions/runs/46000842675)、[Windows](https://github.com/trade3403/localtunnel/actions/runs/46000842672)。不合并 main，继续全部旧门禁。

## 第一增量：控制协议与信任边界（历史设计）
遵循 architecture-and-roadmap.md 第 07 节。现有 nodes 只是共享目录，enabled 不代表在线；现有 runtime worker 直接连接同机 SQLite，不可直接部署为远程节点。

- 管理中心持有唯一权威数据库、租户及分配代际。中转节点独立进程、独立私有目录，通过版本化控制接口交换最小状态，不获得管理数据库、租户密码或管理员 token。业务流量不经过管理中心。单机仍运行同样的协议及节点组件。
- 第一步独立节点身份：可信本地 CLI 针对已存在节点发放随机高熵凭据，服务端仅存摘要；节点凭据只能读取自身状态及提交自身健康信息，不得调用租户 API。可轮换、吊销、审计；旧凭据立即失效。不将明文输出至 CI 证据或日志。已有目录记录默认未注册，不改变 ID。
- 控制协议拟用 /api/v1/relay 路径；首版仅本机回环测试，真实远程使用前必须落实 TLS 服务端身份验证及节点凭据校验、端点配置与私有凭据文件。禁止把回环 HTTP 示例公开到公网。
- 心跳不等于隧道已转发。服务端接收时间决定健康新鲜度；节点报告容量只是声明，不能直接增加已授权额度。排空禁止新增分配但允许有期限存量业务，节点停用、失联及陈旧代际不得取得新授权。
- 后续引入精确分配 ID、mapping revision、node ID、单调代际、有效期限及最小资源预算。节点只执行已验证且未过期授权；离线不允许新增、续期、扩大预算。旧授权不能与新节点同代际并存；故障切换须有明确隔离/到期条件。恢复先对账并拒绝陈旧版本。须考虑重启及可信时钟，不能直接把旧 worker 的数据库访问移植到节点。
- 跨节点商业额度由中心先分配有界预算，节点实际执行；未知预算保守保留，不能因心跳过期就重复分配。此处不预设最终签名/租约格式，先实现身份、隔离及真实测试，再实现授权协议。

## 验收次序
1. 独立身份、轮换、吊销、既有目录迁移、权限隔离。
2. 独立节点进程、私有凭据、认证心跳，至少三个实际进程。
3. 容量、排空、状态及版本化调度，节点间端口独立。
4. 受控真实数据平面迁移、分配代际及有期限授权，管理中心断开时既有授权内转发，到期关闭。
5. 跨节点额度、恢复对账、故障切换、单机向多节点迁移。
6. 监控告警、安全与完整回归，真实证据门禁。

## 当前实现：身份、心跳、运营策略（第三增量 A）
基线 b22c1f96470ac6941734713cc0b02b40f5e34cf8 已验收独立身份、轮换、吊销及三个 Linux 回环控制进程。仍未实现远程 TLS 或独立业务转发。

0020 迁移保留原节点、身份与映射。新旧节点默认 approved_capacity=0、region=unassigned、policy_mode=active、policy_revision=1。可信本地操作员可执行：

- `localtunnel-server --node-health <data-dir> <node-id>`
- `localtunnel-server --set-node-policy <data-dir> <node-id> <expected-revision> <approved-capacity> <region> <active|draining|maintenance>`

策略 CAS 与审计同事务；容量 0–65536，区域为 1–32 个小写 ASCII 字母、数字、下划线或连字符。节点凭据只可 GET /api/v1/relay/policy 查看自身状态，租户目录兼容且不暴露全局运营数据。状态区分 disabled、unregistered、revoked、awaiting_heartbeat、online、offline；只使用当前 generation 的心跳与数据库 UTC 时钟。candidate_capacity 仅在 active、启用、凭据有效且心跳新鲜时为批准及申报容量的较小值；否则为 0。它不是剩余槽位、分配、商业额度或业务授权。draining/maintenance 目前仅影响候选资格，不控制旧版运行时，也不释放任何资源。后续真实调度必须原子复核策略和健康，不能依赖此前读取的候选快照。

备份恢复保留运营策略和审计，吊销快照内有效节点凭据并清空心跳。恢复仍要求当前完整迁移清单；不支持直接恢复旧版本快照，须遵守离线隔离流程。未来分配代际及跨恢复防回滚仍需独立协议设计。

本阶段未部署公网、未增加依赖。第三增量 B/C 继续实现排空门禁、原子分配及端口冲突；未验收前不得称为生产多节点系统。

## 第三增量 B：排空准入与已领取业务保护
排空或维护的运营策略变更在同一事务内停止未领取的 queued 运行请求；claim 写入原子复核节点启用和 active 策略。拒绝新的租户映射草稿及四协议运行请求；active 恢复后可提交新请求，旧队列不会自动复活。旧目录未注册节点仍保留本地开发预览兼容性，不将其误认为远程调度候选。正在执行、停止中及未知请求不被策略更新清除，也不释放商业额度。可信本地手工 export/gateway/supervise 在入口检查节点策略，清空网关仍允许；手工操作不是持久分配，仍需操作员协调并发，不能当作分布式授权。已领取的请求可继续受原有限制，不扩大权限；真正有期限授权在后续阶段实现。维护标签与停用分离，本阶段不声称维护前已验证所有资源清空。
真实 TCP CI 增加未领取请求取消、排空后拒绝新草稿和运行请求、正在转发的数据及原预留保留、正常停止和恢复调度。第三增量 C 将实现独立调度记录及容量原子准入；本阶段不授予节点数据平面权力。

## 第三增量 C：控制面原子资源预留
0021 新增 relay_allocations，使用原有映射表的节点/端口唯一性及租户、设备、域名约束。POST /api/v1/allocations 接受 32 位小写十六进制 request_key、device_id、protocol、local_port、bind_port，可选 region、node_id、domain_id。严格匹配指定区域和节点；否则按已有映射数量、节点 ID 稳定排序。数据库单写事务选择当前有效凭据/新鲜心跳、active 节点，容量取批准与申报的较小值并保守计入所有原有映射。映射、预留、审计原子提交。GET /api/v1/allocations/{id} 仅租户自身可见；POST /api/v1/allocations/{id}/cancel 需精确 expected_generation，仅释放从未获得执行权的 reserved 记录，保留 cancelled 历史及幂等键；相同请求返回原结果，不复活已取消记录。不同请求复用同键拒绝。心跳、吊销、排空或停用不会自动释放任何预留。
新预留仅为 desired metadata，不提供节点执行权，generation=1 为初始占位，未来租约阶段才引入重新分配和单调代际推进。旧映射保留；已注册节点的新草稿须经调度入口，旧本地运行接口禁止执行新预留。备份恢复保留预留和历史；凭据撤销、设备禁用后仍须重新授权，不能自动继续转发。尚未执行独立节点数据面或跨节点商业运行配额。

## 第四增量 A：认证 HTTPS 控制通道
Linux 节点可运行 `localtunnel-relay --tls <private-dir> <host> <port> <node-id> <generation> <capacity>`。目录为当前 UID 所有、0700；relay.token 与 center-ca.pem 为当前 UID 所有、0600、普通单链接文件。CA 文件最大 64 KiB。沿用现有 OS curl（/usr/bin/curl，要求 8.4+，OpenSSL 后端），不增加 Cargo 依赖。证书链及主机名检查不可关闭；只允许 HTTPS、TLS 1.2+、HTTP/1.1，无重定向、代理或明文降级。清空 curl 环境且禁用默认配置；凭据通过子进程标准输入配置传送，不写入命令行、环境或诊断输出。连接与请求有界，证书及协议错误停止进程；网络故障按原控制协议重试。旧回环 HTTP 模式仅供本机开发。
deploy/relay-control-nginx.conf.example 为专用 HTTPS 入口模板，实际部署须替换全部占位符并验证配置；只开放三个精确节点控制接口，管理/租户 API 不开放，中心保持 127.0.0.1。需操作员配置真实 DNS、证书、私钥和网络访问控制。CI 使用隔离 CA 和真实 nginx TLS 连接，不需要公网资源。未部署公网；后续仍需远程业务授权协议、独立数据面、证书更新与生产运维验证。

## 第四增量 B：版本化策略同步
POST /api/v1/relay/control 是新节点程序的唯一同步接口，旧 identity/heartbeat/policy API 仍兼容既有调用，但新程序不会回退旧协议。请求必须匹配协议版本 1、节点 ID、凭据代际、容量和随机 128 位 nonce；不允许未知字段。认证、心跳写入及当前策略查询在单个 SQLite 写事务中完成。响应回显 nonce，声明 scope=control_only，仅返回自身策略及数据库接收时间。独立节点校验响应身份、协议、nonce、字段和策略值；同一进程拒绝策略修订号倒退或同版本策略内容改变。网络错误重试仍保留上一观察修订号，策略快照不是执行授权。TLS 入口仅额外允许此精确 POST 路径。真实 CI 增加拒绝非法请求且不更新心跳、原子策略响应、独立节点运行中接收策略修订测试。跨进程/跨恢复的反回滚及离线有效期执行属于第五增量，尚未完成。

## 第五增量 A：限时授权账本（不可执行预览）
0022 增加 relay_grants。租户 POST /api/v1/allocations/{id}/grant 提供 expected_generation=1、expected_mapping_revision；原子复核节点身份、健康、active 策略、保守容量、所有者/设备/租户当前权限。仅允许 TCP 且未配置有限带宽/月流量/并发预算的计划（跨节点预算尚未实现）。写入 15 秒固定预览，分配 generation 从 1 原子推进至 2，并记录节点凭据、映射、设备、策略、权益修订与审计。每个分配仅可签发一次，重复申请拒绝，GET 同路径可查询历史。节点 POST /api/v1/relay/grant 必须提供完整绑定及 nonce，当前凭据及状态、版本和期限均通过才返回 scope=authorization_preview_only。不会续期、自动切换或签发实际执行许可。过期、策略变化、吊销、恢复不释放资源；取消曾签发分配被数据库和 API 双重阻止。恢复标记历史授权撤销，仍保留资源。未来增加经过隔离验证的回收与重新分配；未实现离线验证或真实业务执行。

## 第五增量 B：独立节点限时授权预览校验
新增 Linux TLS 专用命令 `localtunnel-relay --verify-grant <private-dir> <host> <port> <node-id> <node-generation> <capacity> <allocation-id> <mapping-id> <mapping-revision> <allocation-generation> <grant-id>`，由可信操作员提供预期 ID 和版本，不自动发现授权。先同步当前节点策略，再获取精确授权；检查协议版本、随机 nonce、scope、授权/分配/映射/节点标识、各代际与策略版本、撤销状态、有效期限。中心在同一查询返回 server_time；节点以请求开始单调时间加剩余秒数并扣除一秒量化误差计算保守观察截止，不以响应抵达延长期限。不缓存、不续期、不接受过期重新启动、不创建数据面监听器。观察期间只输出固定状态文字，到保守期限退出；不代表实时撤销执行或离线许可，不能作为实际流量准入。下一增量须落实数据面绑定、可执行授权与实际资源停止，之后才能验证离线及故障切换。CI 新增真实 TLS 节点正确/错误绑定和过期重启拒绝，以及本地校验单元测试。

## 第六增量 A：TCP 数据面显式启动意图与一次性领取
0023 增加 relay_tcp_intents。已签发的非执行性预览不能自动转成执行权限；租户须 POST /api/v1/allocations/{id}/tcp-intent，提交 grant_id、expected_generation 和 30000–59999 的 relay_port。写事务重新检查当前授权、所有权、容量、策略及商业权益，固定此前预留的 bind_port；同一节点的 relay_port 唯一，未对账不得重复使用。只接受 TCP、回环预览及无有限运行商业额度的计划。节点 POST /api/v1/relay/tcp-claim 提供精确授权、分配、映射、节点和代际及 relay_port、nonce；原子领取一次，返回 tcp_loopback_start_claim 与固定端口、当前时间及原授权期限。过期、策略修改、凭据轮换、恢复均不能领取；重复领取即使响应丢失也拒绝。仅暴露精确 TLS POST 路径，不开放租户接口。账本保留，未完成安全对账不回收端口。此增量仅提供一次性启动领取协议，尚未连接真实 Rathole 监听器，不代表实际数据面启动或生产可用。

## 第六增量 B：独立回环 Noise TCP 数据面
Linux 节点 `--tcp-preview` 参数为 --verify-grant 的参数再附加 relay-port、bind-port、absolute-engine。可信本地操作员必须预置当前 UID 私有目录中的 noise.private（X25519 私钥）和 tcp.token（独立随机 64 位十六进制服务 token），可信已校验 Rathole 路径；客户端单独持有对应公钥与服务 token。节点生成固定回环 Noise 配置，不接受任意 TOML 或外部目标，不访问中心数据库。启动前验证端口、同步策略并原子领取明确 TCP intent，核对全部 ID、代际、端口、nonce、服务器时间与固定期限；领取不可重放。只在本地单调保守期限内运行直接子进程，Linux 父进程死亡信号防止直接子进程脱离监管。正常到期 kill/wait 后删除配置；崩溃遗留文件保留供检查。真实 CI 使用同机独立节点、独立加密 agent 和 HTTP fixture，验证实际 TCP 传输、重复启动拒绝、到期后两个端口关闭。暂不支持公网监听、自动分发业务密钥、长期续期、运行中即时撤销或跨节点商业额度。端口及授权记录仍保留等待对账。当前试验期限只有 15 秒；不是生产租约。
