## 桌面端候选功能
- Tauri 2 + Vue 3 工作台；可配置中转地址、服务端 Noise 公钥、经过校验的 Rathole EXE 绝对路径，添加/删除 1–64 个本地映射。
- 每映射独立 token，UI 密码字段遮挡；Rust 复用原核心验证名称、端口、token、公钥及重复映射规则。本地地址固定 127.0.0.1。
- 真实 Tauri IPC 启动和停止 Rathole 子进程。临时配置仅在进程生命周期内存在，正常停止/通过托盘退出会清理；不写持久凭据。进程运行不等于已连接，不虚构公网在线状态。引擎日志暂不展示，避免泄露凭据。
- 需要管理员提前在中转服务端配置同名映射、授权 token、域名。界面暂不直接分配域名或修改服务端。
- 开发预览默认不随系统启动；关闭主窗口后隐藏到系统托盘，当前登录会话内继续运行，不是 Windows Service。强制结束进程或系统异常后的子进程/临时文件清理仍需专项测试。Windows 临时目录依赖当前用户 ACL；生产版本需凭据保护和 Windows Job Object/Service。

## Windows 本地开发
安装 Rust stable MSVC、Visual Studio C++ build tools、Node.js、WebView2 及 Python。进入仓库根目录：
    
    python apps/desktop/scripts/create_icons.py
    cd apps/desktop
    npm install
    npm run tauri -- dev

构建预览安装包：npm run tauri -- build --bundles nsis 。Rathole v0.5.0 需从官方来源获取并校验；本预览不随安装包内置引擎，操作员填写可信 EXE 路径。依赖锁文件由首次 CI 产生并留档，后续审查并提交 lockfile 才视为可复现构建。

## 系统托盘与非秘密配置增量（待 CI）

- Tauri 原生托盘菜单：显示主窗口、停止隧道、退出 LocalTunnel。关闭主窗口隐藏到托盘，退出前停止受管子进程。只支持当前登录会话内常驻，不声称已实现 Windows Service、注销后运行或开机自启。
- 保存/读取配置需要明确点击，运行时禁止编辑；保存到当前用户 app_config_dir/profile.json。原子替换 JSON，大小限制 128 KiB，Rust 核心校验节点地址、端口、映射名称和公钥。严格拒绝未知字段（包括 token）；仅保存非秘密配置，读取后必须重新输入各映射 token。不会自动启动隧道。公钥不是私钥。普通配置保存不使用 DPAPI；本阶段另外新增显式加密保存功能（见下）。
- 新增配置文件往返、覆盖、无 token、非法端口、未知字段和超限测试。Windows 桌面工作流继续执行真实隧道进程及 NSIS 安装包构建；托盘真实点击、系统注销和异常终止仍待验收。

## 凭据保护与本地端口诊断增量（独立分支，待 CI）

- 用户可主动选择“加密保存含 Token”，通过 Windows DPAPI CurrentUser 加密完整配置及映射 token，原子替换当前用户配置目录中的 protected-profile.bin；禁用机器级保护和交互提示，不提供明文回退。
- “读取加密配置”只恢复表单，不启动引擎；“删除加密凭据”删除加密文件并清空表单 token。普通 profile.json 仍不含 token；两种保存互相独立。DPAPI 不防御已控制当前 Windows 账户的程序，也不是安全擦除；运行中的 Rathole 仍需临时明文配置文件，异常终止清理仍待验证。
- 每条映射可显式检测 127.0.0.1 本地 TCP 端口，显示指定端口的可达/不可达结果。检测不传输业务数据、不探测公网，不能代表隧道认证、服务端在线或 HTTP 应用健康。Rust 测试使用真实回环 listener 验证开放/关闭/非法端口。
- 新增 Windows DPAPI 实际加解密往返、覆盖、磁盘无明文 token、非法密文拒绝及删除测试；沿用现有 Windows CI 安装包与真实隧道生命周期测试。尚未取得该增量的 CI 结果，不承诺通过。
- V0.3 基线 CI #17（https://github.com/trade3403/localtunnel/actions/runs/45420554737）最终 Vue 构建和 5 项 Rust 单测通过；真实生命周期测试在 server_config 校验生成的私钥时失败，NSIS 构建未执行。已在增量分支修正测试密钥提取：按已通过的 Python E2E 提取紧邻标签的 Base64 token，新增尾部输出及无效 key 回归测试，保留原核心验证；修复仍待 CI。本增量使用独立分支和 PR，避免因继续提交而取消基线构建。

## V0.3 进程可靠性与安装验收增量（待 CI）

Windows 引擎启动采用独立、不可继承的 Job Object，设置 JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE。启动后立即关联子进程；关联失败时拒绝启动并尝试终止子进程。关联成功后桌面进程异常退出导致最后一个 job handle 关闭时，Windows 负责终止关联引擎。真实 Windows 单测启动一个睡眠进程、关联 job、关闭句柄并验证进程退出。现有 Rathole 真实生命周期测试也走相同启动路径。

限制：spawn 至关联之间仍有短暂竞态；异常退出后临时配置文件可能残留。这不是 Windows Service，也不代表开机启动或跨注销运行。未实施系统级自启动。

安装包门禁：Windows 免费 Runner 构建 NSIS 后，执行隔离目录静默安装、启动安装后的原生窗口、停止测试程序、静默卸载并验证程序文件移除，输出 installer-smoke.json。全部通过才上传预览安装包。此检查不等于 GUI 点击、托盘交互、真实公网或签名验收；若 hosted runner 无可用桌面，需明确记录失败并另行解决，不跳过伪造通过。
